## 数据与规模

用户指定二阶截断 7.0 Å、三阶截断 4.5 Å。原始数据 700 构型、496 原子，
最后一个构型是未位移参考，剩余 699 构型用于拟合。原数组的原子顺序不同于
SPOSCAR；通过周期几何匹配获得双射，并同时重排坐标和力，参考匹配最大误差
7.13e-15 Å。减去参考帧残余力后使用笛卡尔位移；位移 RMS 为 0.0173014 Å。

全量建表成功：SM_prime 为 1,040,112×66,375，3,780,068,976 个非零项，
float64，共 60.49 GB。约束后 52,283 个参数，其中二阶 10,252、三阶 42,031。
完整稠密乘积需要约 435 GB，使用 TwoLevelSM 避免生成该乘积。
结构/约束作业 1507 完成；建表作业 1508 耗时 46:53，SLURM MaxRSS
151,410,516 KiB。后续拟合复用此唯一缓存。

## 已修复并有测试覆盖的问题

| 问题 | 修复与证据 |
|---|---|
| 分数坐标数据与 SPOSCAR 原子顺序不一致 | 新增 `--align-reference`，位移和力使用同一几何双射；数据准备回归及真实几何匹配 |
| `python -m pheasy_gpu.run_pheasy` 没有执行入口 | 添加主模块入口；真实结构、约束、建表与全链路测试实际执行 |
| 显式 OLS 硬编码 float32，并引用尚未初始化的局部 sparse 模块 | 保持用户设置精度并使用已导入模块；CPU/GPU 显式独立谐波全链路通过 |
| 紧凑 fc3 仍先申请完整超胞张量 | 直接分配原胞代表的第一维；本例数组需求由约 26.36 GB 降至 3.29 GB；紧凑输出与完整输出切片逐元素一致 |
| HDF5 fc2 回读的形状判断恒不通过、文件关闭后仍使用 Dataset | 接受有效四维布局，文件关闭前读成数组；完整/紧凑及三种键名回读测试通过 |
| 算子 ridge 子问题的闭包引用增强后自身 | 捕获原始算子；与独立正规方程解对照通过 |
| RFE 删除至最少特征后没有评价该候选 | 评价最后候选再选模型；CV/BIC/AIC 最少特征测试通过 |
| Jacobi 与 ridge 组合改变原始惩罚目标 | 按原始系数单位构造惩罚块；与独立带岭解对照通过 |
| Jacobi 的宽泛异常处理会将求解错误误当成缩放准备失败 | 显式请求缩放时传播错误，不悄悄重跑；异常注入测试确认只求解一次 |
| 迭代达到上限仍可被当成成功 | 暴露 LSQR/LSMR 停止诊断，非收敛告警；验证驱动严格拒绝，真实作业 1512 已被正确拒绝 |
| GPU 索引溢出或单卡块超出可用显存，回退后残留资源 | int32 索引及块内存预算检查，初始化/运行失败关闭块并禁用巨型主机转置缓存；模拟错误测试与真实多卡运行 |
| RFE-OLS-TSQR 不正确进入指定的 TwoLevelSM 路径 | 接通算子路径，明确子问题使用 LSMR；真实多卡小矩阵对照 |
| dtype 转换及建表临时对象增加大矩阵内存 | 避免无必要的稀疏矩阵副本，释放已聚合结果；真实 60 GB 矩阵装载与六卡运算记录 |
| 稠密缓存未充分区分约束和排除构型 | 缓存键纳入约束内容、排除构型和纳秒时间戳 |
| 包装脚本默认使用旧可执行程序 | 默认 `pheasy-gpu`，支持显式程序路径并验证；带空格路径回归通过 |

## 限制和解释

- 所有通过结论限于已测试的硬件、数据、精度和路径，不能证明不存在其他 bug。
- 真实数据训练误差低不代表物理可靠。独立 20 构型验证用于比较 OLS 与 RFE；
  还没有声子色散、热导率或跨温度/体积验证。
- 本例六卡存储矩阵行块及转置块，NS 和迭代控制仍在 CPU；并非将六卡显存合成一块稠密内存。
- 每卡分块必须独立满足显存和 int32 限制；极不均匀稀疏结构可能仍不适用。
- 精确列范数增加 CPU 准备时间。秩亏时，缩放可能改变非唯一解中的系数选择；
  比较预测与残差，不能要求所有方法选取相同系数。
- 资源 JSON 的 GPU 数字是 PyTorch 分配/保留量，不包括 CUDA 上下文及其他进程。
- 全量 float32、四阶 IFC、全部方法的全量材料拟合和多节点运算未覆盖。
